# Nudget

บันทึกรายรับรายจ่ายผ่าน **LINE chatbot** แล้วดูสรุปบน **เว็บแดชบอร์ด**

- Production: https://nudget-production.up.railway.app
- Source: https://github.com/YannawutRoumsuk/Nudget-Project

พิมพ์ `ข้าวเที่ยง 60` ในแชท LINE → บอทแยกจำนวนเงิน หมวดหมู่ และวันที่ให้เอง →
แดชบอร์ดแสดงยอดรายวัน สัดส่วนตามหมวดหมู่ และรายการทั้งหมด

---

## Stack

| ส่วน | เทคโนโลยี |
|------|-----------|
| Web + API | SvelteKit 2 (Svelte 5 runes) |
| DB | PostgreSQL 17 + Drizzle ORM |
| Chat | LINE Messaging API (webhook + reply) |
| OCR | Sharp + Tesseract.js (ไทย/อังกฤษ) |
| Parser | rule-based ก่อน แล้ว fallback ไป LLM (Anthropic หรือ Gemini) |
| Charts | inline SVG เขียนเอง — ไม่มี chart library |

---

## เริ่มใช้งาน (local)

```bash
cd D:/Coding/spendbot
cp .env.example .env      # ถ้ายังไม่มี
bun install
bun run db:setup          # docker compose up + push schema + seed หมวดหมู่
bun run dev               # http://localhost:5173
```

`db:setup` เท่ากับ `db:up` → `db:push` → `db:seed`

เข้าแดชบอร์ดด้วยรหัสผ่านจาก `DASHBOARD_PASSWORD` ใน `.env`

## ต่อ LINE bot

1. สร้าง **Messaging API channel** ที่ [LINE Developers Console](https://developers.line.biz/console/)
2. คัดลอกค่าลง `.env`
   ```
   LINE_CHANNEL_SECRET=...        # แท็บ Basic settings
   LINE_CHANNEL_ACCESS_TOKEN=...  # แท็บ Messaging API (กด Issue)
   ```
3. เปิด tunnel ให้ webhook เข้าถึงเครื่องได้
   ```bash
   cloudflared tunnel --url http://localhost:5173
   ```
   Quick Tunnel จะได้ hostname ใหม่ทุกครั้งที่เปิด ต้องเปิดหน้าต่างนี้ค้างไว้และอัปเดต Webhook URL เมื่อ hostname เปลี่ยน
4. ใส่ Webhook URL เป็น `https://<tunnel>/api/line/webhook` แล้วกด **Verify**
5. ปิด *Auto-reply messages* และเปิด *Use webhook* กับ *Webhook redelivery* ในหน้า Messaging API
6. แอดบอทเป็นเพื่อน แล้วพิมพ์ `ไอดี` — บอทจะตอบ LINE userId กลับมา
   นำไปใส่ `LINE_ALLOWED_USER_ID` เพื่อประกาศตัวเป็นเจ้าของ

> ถ้า `LINE_ALLOWED_USER_ID` ว่าง บอทจะบอก userId ให้อย่างเดียว ยังใช้บันทึกอะไรไม่ได้ หลังตั้งค่า `.env` ให้ restart dev server

### ให้คนอื่นใช้

**เพื่อนแค่แอดบอทเป็นเพื่อน แล้วใช้ได้เลย** — ไม่มีรหัส ไม่ต้องพิมพ์อะไร บอทเปิดบัญชีให้ทันทีที่แอด ส่ง QR หรือลิงก์แอดเพื่อนของ LINE OA ให้เขาก็พอ

แต่ละคนได้บัญชีของตัวเองแยกกันสมบูรณ์ — รายการ บิล แผนเดือน และสรุปมองไม่เห็นกัน และเตือนบิลส่งเข้า LINE ของเจ้าของบิลเท่านั้น

ไม่มีเพดานจำนวนคน ตัวกั้นคือ **ลิงก์แอดเพื่อนของ LINE OA** ที่คุณเป็นคนส่งให้เอง (ตั้ง OA ไม่ให้ค้นหาเจอ) แทนที่จะกั้นไว้ก่อน ระบบเลือกวิธี **มองเห็นทุกคนที่เข้ามา** แล้วปิดสิทธิ์ทีหลังได้ทันที

### มอนิเตอร์ว่าใครเข้ามาบ้าง

มีสามทาง:

1. **แจ้งเตือนทันที** — มีคนใหม่แอดบอท เจ้าของทุกคนได้ข้อความบอกชื่อ LINE, LINE id และเวลาที่เข้ามา
2. **หน้า `สมาชิก` บนเว็บ** (`/members`, เห็นเฉพาะเจ้าของ) — ตารางทุกบัญชี: ชื่อ LINE, LINE id, เข้ามาเมื่อไหร่, บันทึกไปกี่รายการ, ใช้ล่าสุดเมื่อไหร่ พร้อมปุ่มปิด/เปิดสิทธิ์
3. **พิมพ์ `สมาชิก` ในแชท** — ดูรายชื่อย่อจากมือถือได้เลย

หน้าสมาชิกสรุปให้ด้วยว่ามีกี่คนใช้งานอยู่ กี่คนถูกปิดสิทธิ์ และกี่คนที่แอดมาแต่ยังไม่เคยบันทึกอะไร — ตัวเลขสุดท้ายคือสัญญาณว่ามีใครแอดมาโดยไม่ได้ตั้งใจใช้จริง

**ปิดสิทธิ์** กดปุ่มในหน้าสมาชิกได้เลย (หรือ `update users set active = false where line_user_id = '...'`) — ไม่ลบแถว เพราะการลบ user จะ cascade ลบรายการเงินทั้งหมดของเขาไปด้วย คนที่ถูกปิดสิทธิ์กลับเข้ามาเองไม่ได้ ต้องให้เจ้าของเปิดให้ แล้วข้อมูลเดิมกลับมาครบ

สิทธิ์เจ้าของมาจาก `LINE_ALLOWED_USER_ID` เท่านั้น ปิดสิทธิ์เจ้าของจากหน้าเว็บไม่ได้ ต้องเอา id ออกจากตัวแปรก่อน — กันไม่ให้เผลอล็อกตัวเองออกจนไม่มีใครแก้คืนได้

### ล็อกอินเข้าเว็บ

เข้าผ่าน **LINE login (LIFF)** กดปุ่มเดียว ไม่มีรหัสผ่านของ user แต่ละคน — ตัวตนคือ LINE account ของเขาเอง ใช้ได้ทั้งในแอป LINE และเบราว์เซอร์บนคอม (ตั้ง `withLoginOnExternalBrowser: true` ไว้) session อยู่ 30 วันต่อเบราว์เซอร์ ต้องตั้ง `LIFF_ID` ก่อน

การ login **ไม่สร้างบัญชีให้** ต้องแอดบอทใน LINE ก่อนเสมอ — หน้า login จึงแสดง QR และ @id (`LINE_ADD_FRIEND_ID`) ไว้ให้คนที่มาเจอเว็บก่อน และถ้ากด login ทั้งที่ยังไม่มีบัญชี บอทจะบอกตรง ๆ ว่าให้ไปแอดก่อน

QR ถูก generate ไว้ล่วงหน้าเป็น `static/line-add-friend.svg` ไม่ได้ดึงจาก LINE ตอนเปิดหน้า — เปลี่ยน id แล้วต้องรัน `bun run line:qr` ใหม่:

```bash
bun run line:qr
```

`DASHBOARD_PASSWORD` เป็นรหัสร่วม บอกไม่ได้ว่าใครเป็นใคร มันจึงเข้าสู่ระบบเป็น**เจ้าของ**เสมอไม่ว่าใครกรอก ใช้ได้เฉพาะตอนมีเจ้าของคนเดียว และช่องกรอกถูกซ่อนไว้ใต้ “สำหรับแอดมิน” ถ้าไม่ได้ใช้ ให้ลบตัวแปรทิ้งไปเลย

## บันทึกหลายรายการในข้อความเดียว

พิมพ์บรรทัดละรายการ ส่งทีเดียว:

```text
กาแฟ 60
น้ำ 30
ข้าว 50
```

บอทบันทึกครบทั้งสามรายการแล้วตอบยอดรวมกลับมา บรรทัดไหนอ่านไม่ออกจะบอกว่าข้ามบรรทัดไหนไป ไม่เงียบหาย

**ตัวแบ่งคือการขึ้นบรรทัดใหม่เท่านั้น ไม่ใช่ช่องว่าง** เพราะภายในบรรทัดเดียวกันตัวเลขโดด ๆ อาจเป็นส่วนหนึ่งของชื่อรายการ — `ข้าว 2 จาน 120` คือข้าวสองจานราคา 120 ไม่ใช่สองรายการ ถ้าแบ่งด้วยช่องว่างจะได้รายการที่ไม่มีใครพิมพ์

ถ้ามีบรรทัดเดียวที่มีจำนวนเงิน ระบบถือว่าเป็นรายการเดียวที่ข้อความยาวจนขึ้นบรรทัดใหม่ ไม่ใช่ลิสต์

> ข้อจำกัดที่รู้ตัว: หลายยอดใน**บรรทัดเดียวกัน** ที่ไม่ใช่แผนผ่อน เช่น `ค่าของ 4050 3800` ยังบันทึกแค่ยอดสุดท้าย เพราะแยกไม่ได้ว่าเป็นลิสต์หรือชื่อรายการ ให้ขึ้นบรรทัดใหม่แทน

## ผ่อนหลายงวด

พิมพ์จำนวนเดือนกับยอดแต่ละงวดในบรรทัดเดียว:

```text
บิล shoppe 3 เดือน 4050 3800 3800
```

ระบบตั้ง **บิลล่วงหน้า 3 ใบ** เดือนละใบ เรียงตามลำดับที่พิมพ์ ครบกำหนดวันเดียวกับวันที่พิมพ์ในเดือนถัด ๆ ไป:

```text
🧾 ตั้งบิลล่วงหน้า 3 งวด

บิล shoppe

งวด 1 · 4,050 บาท · ครบ 6 ก.ย.
งวด 2 · 3,800 บาท · ครบ 6 ต.ค.
งวด 3 · 3,800 บาท · ครบ 6 พ.ย.

รวม 11,650 บาท
```

ยอดเท่ากันทุกงวดพิมพ์ยอดเดียวพอ: `ผ่อนมือถือ 4 เดือน 1500`

เงื่อนไข: ต้องมีคำว่า **บิล / ผ่อน / งวด** ในข้อความ ไม่งั้น `ค่าเน็ต 3 เดือน 1500` จะกลายเป็นบิลสามใบทั้งที่เป็นรายจ่ายเดียว และจำนวนยอดต้องเท่ากับจำนวนเดือนพอดี หรือมียอดเดียว — นอกนั้นถือว่ากำกวม ปล่อยให้ parser ปกติจัดการ

บิลพวกนี้เป็น**เงินที่ยังไม่ได้จ่าย** ไม่ใช่รายจ่ายที่เกิดแล้ว กดจ่ายทีละงวดที่หน้า `บิล` แล้วระบบจะสร้างรายจ่ายจริงให้ตอนนั้น วันที่ 31 ในเดือนที่ไม่มีวันที่ 31 จะเลื่อนเป็นวันสุดท้ายของเดือน ไม่ข้ามไปเดือนถัดไป

ช่องกรอกด้านบนแดชบอร์ดใช้ parser ตัวเดียวกัน วางลิสต์หลายบรรทัดลงไปได้เหมือนกัน

## Rich Menu ภาษาไทย

สร้างภาพเมนู 6 ช่องขนาด 2500x843 โดยไม่เรียก LINE API:

```bash
bun run line:rich-menu
```

ตั้ง `PUBLIC_BASE_URL` เป็น URL HTTPS ของแดชบอร์ด แล้วใช้ `--setup` เพื่อสร้าง อัปโหลด และตั้งเป็นเมนูเริ่มต้นผ่าน LINE API (คำสั่งนี้ส่งคำขอจริง):

```bash
bun run line:rich-menu --setup
```

ภาพที่สร้างอยู่ที่ `static/line-rich-menu.png` และปุ่ม `สรุป`/`ช่วย` ส่งข้อความ `เดือนนี้`/`ช่วย` กลับเข้าแชท

> Rich menu แสดงเฉพาะแอป LINE บนมือถือ บน iPad และ LINE บนคอมมักไม่ขึ้น — พิมพ์ `เว็บ` เพื่อขอลิงก์แดชบอร์ดแทนได้

ช่องกรอกด้านบนแดชบอร์ดใช้ parser ตัวเดียวกัน — พิมพ์แบบเดียวกับในแชทได้เลย

เว็บมีหน้า `บิล` สำหรับค่าใช้จ่ายรายเดือน/ครั้งเดียวและยอดบัตรเครดิต กดจ่ายแล้วจะสร้างรายจ่ายจริงให้ทันที หน้า `แผนเดือน` ใช้รายรับ เป้าหมายออม ค่าอาหาร ค่าเดินทาง รายจ่ายจริง และบิลค้างเพื่อคำนวณยอดที่ยังใช้ได้ รายการทุกแหล่งอยู่ใน PostgreSQL เดียวกัน จึงแก้จากเว็บแล้วเห็นผลในสรุป LINE ทันที

ปุ่ม `คัดลอก` ในบิลจะเปิดฟอร์มสร้างบิลใหม่พร้อมรายละเอียดเดิม ให้แก้ยอดหรือวันก่อนยืนยันได้ โดยไม่คัดลอกสถานะและประวัติการชำระ

หน้า `ภาพรวม`, `รายการ` และ `แผนเดือน` ใช้ตัวเลือกเดือนเดียวกัน เดือนที่เลือกอยู่ใน query `month=YYYY-MM` จึงส่งลิงก์หรือ bookmark ไว้ได้ และเมนูหลักจะรักษาเดือนเดิมเมื่อเปลี่ยนหน้า

หน้า `ส่งออก` เลือกได้ทั้งรายเดือนและช่วงวันที่ ดาวน์โหลดธุรกรรมหรือบิลเป็น CSV ที่เปิดภาษาไทยใน Excel/Google Sheets ได้ และดาวน์โหลด JSON ที่รวมแผนรายเดือนกับประวัติชำระบิลของบัญชีที่เข้าสู่ระบบ ข้อมูลส่งออกไม่รวม LINE user ID หรือข้อความดิบจากแชท

OCR ใช้ Gemini Vision เป็นทางหลักเมื่อมี `GEMINI_API_KEY` โดยย่อรูปเหลือไม่เกิน 1024px ก่อนส่ง และถอยไป Tesseract ภาษาไทย/อังกฤษเมื่อ API ใช้ไม่ได้ ค่า confidence ต่ำจะแสดงเตือนให้ตรวจยอด วันที่ หรือผู้รับก่อนกดบันทึก ซึ่งทุกสลิปต้องยืนยันอยู่แล้ว ตั้งเพดานต่อคนได้ด้วย `OCR_DAILY_LIMIT`; ระบบเก็บเฉพาะจำนวน token และสถานะ ไม่เก็บรูปหรือข้อความสลิปใน metric หากต้องการไม่ส่งรูปออกจากเครื่องให้ตั้ง `OCR_PROVIDER=tesseract`

ระบบเตือนบิลทำงานเมื่อเซิร์ฟเวอร์เปิดอยู่ ตั้งเวลาไทยด้วย `REMINDER_HOUR` และจำนวนวันล่วงหน้าด้วย `REMINDER_DAYS_BEFORE`

## Deploy บน Railway

โครง production ที่ประหยัดสำหรับบัญชีส่วนตัวมี 3 services ในโปรเจกต์เดียว:

- `web`: รับ LINE webhook และให้บริการ dashboard เปิด Serverless และมี public domain
- `Postgres`: เก็บข้อมูลกลาง ใช้ private `DATABASE_URL`
- `reminders`: Railway Cron รัน `bun run cron:reminders` เวลา `0 2 * * *` (09:00 Asia/Bangkok) ไม่มี public domain

OCR ทำใน `web` เฉพาะตอนมีรูปสลิป (`OCR_MODE=inline`) จึงไม่ต้องเปิด worker ค้างไว้ ส่วน `bun run worker:ocr` มีไว้สำหรับแยก service ภายหลังเมื่อจำนวนสลิปมากขึ้น

รายละเอียดตัวแปร ขั้นตอนเชื่อม GitHub และการควบคุมค่าใช้จ่ายอยู่ใน [DEPLOYMENT.md](./DEPLOYMENT.md)

## LLM ใช้ตรงไหนบ้าง (ไม่บังคับ)

กฎ regex มาก่อนเสมอ LLM เป็นด่านสองเฉพาะตอนกฎทำไม่ได้ ตั้งค่าอย่างใดอย่างหนึ่งใน `.env`

```
ANTHROPIC_API_KEY=sk-ant-...     # ใช้ claude-haiku-4-5
# หรือ
GEMINI_API_KEY=...               # parser เริ่มที่ gemini-2.5-flash-lite
# หรือผ่าน gateway
OPENROUTER_API_KEY=sk-or-v1-...
LLM_PROVIDER=openrouter
LLM_MODEL=google/gemini-2.5-flash-lite
OCR_MODEL=google/gemini-2.5-flash
```

ปล่อยว่างทั้งหมด = ใช้ rule-based ล้วน ไม่มีค่า API เลย

### เลือกเส้นทางเรียกโมเดล

รองรับสามเส้นทาง คือยิงตรงเข้า Anthropic ยิงตรงเข้า Google และผ่าน OpenRouter
แต่ละเส้นทางใช้ header และรูป request ต่างกัน โค้ดจึงเลือกจากคีย์ที่ตั้งไว้ ไม่ใช่จากชื่อรุ่น

ชื่อรุ่นต่างกันตามเส้นทาง ยิงตรงใช้ชื่อเปล่าเช่น `gemini-2.5-flash-lite`
ผ่าน gateway ต้องมี namespace เช่น `google/gemini-2.5-flash-lite` ตั้งผิดจะได้ 404 แล้วระบบถอยไปใช้กฎ

ตั้งชื่อรุ่นผิดรูปจะมีคำเตือนตอนบูต ไม่ต้องรอให้ผู้ใช้เจอว่าฟีเจอร์เงียบไป

### เช็คว่าคีย์ถึงจริงไหม

ตอนบูตจะมีบรรทัดเดียวใน log บอกว่าตกลงต่ออะไรอยู่ ไม่ได้พิมพ์คีย์ออกมา

```
[config] parser=openrouter:google/gemini-2.5-flash-lite slips=openrouter:google/gemini-2.5-flash
```

ถ้าเห็น `parser=off (no usable key)` แปลว่าคีย์ยังไม่ถึง process และถ้าเห็น
`slips=tesseract (local, no vision key)` แปลว่าลืม `OCR_API_PROVIDER=openrouter`

ถามจากมือถือก็ได้ พิมพ์ `สถานะ` ในแชท เจ้าของจะได้บรรทัดเดียวกัน
และหน้า `วิเคราะห์` จะแสดงให้เจ้าของเห็นด้วยเมื่อผู้ช่วยยังปิดอยู่

นี่คือเหตุผลที่มีสามทาง ทั้งสองฟีเจอร์ปิดตัวเองเงียบๆ เมื่อไม่มี provider
ซึ่งจากข้างนอกดูเหมือนมันพัง ไม่เหมือนว่ายังไม่ได้ตั้งค่า

การอ่านสลิปตั้งแยกด้วย `OCR_API_PROVIDER` เป็น `google` `openrouter` หรือ `none`

**คีย์ OpenRouter เพียงอย่างเดียวจะไม่เปิดการอ่านสลิปให้** ต่างจากคีย์ Google ที่เปิดให้เลย
เพราะรูปสลิปมีชื่อผู้โอน ผู้รับ เลขอ้างอิง และอาจมีเลขบัญชีที่แอปไม่ได้เก็บลงฐานข้อมูล
ส่งผ่าน gateway หมายถึงมีผู้เห็นรูปสองรายแทนหนึ่งราย ซึ่งต้องเป็นการตัดสินใจที่เลือกเอง
ไม่ใช่ผลพลอยได้จากการตั้งคีย์เพื่อให้ parser ถูกลง ถ้าต้องการให้ตั้ง `OCR_API_PROVIDER=openrouter`

แต่ละสลิปบันทึกไว้ว่าใครอ่าน ดูได้จากคอลัมน์ `ocr_provider` ในตาราง `pending_slips`

ราคาต่อการเรียก 1,000 ครั้งบน OpenRouter คิดจากขนาด prompt จริงในโค้ด เรต 36 บาทต่อดอลลาร์

| งาน | google/gemini-2.5-flash-lite | google/gemini-3.1-flash-lite |
|-----|------|------|
| อ่านสลิป | 10 บาท | 32 บาท |
| แยกข้อความ | 3 บาท | 10 บาท |
| บทวิเคราะห์เดือน | 13 บาท | 43 บาท |

ตระกูล 3.x มักเปิด thinking เป็นค่าเริ่มต้น และโทเคน thinking คิดเป็นขาออกซึ่งแพงสุด
ค่าจริงจึงอาจสูงกว่าตาราง ตรวจได้จากตาราง `llm_usage` ที่เก็บโทเคนเข้าออกไว้ทุกครั้ง แยกตาม workflow และเส้นทาง

| งาน | เรียกเมื่อไหร่ | ตั้งค่าที่ |
|-----|---------------|-----------|
| แยกข้อความที่กฎอ่านไม่ออก เช่น `จ่ายค่าข้าวไปห้าสิบบาท` | เฉพาะตอนกฎหายอดหรือหมวดไม่เจอ จำกัดเริ่มต้น 20 ครั้ง/คน/วัน | `LLM_PROVIDER` / `LLM_MODEL` / `LLM_PARSER_DAILY_LIMIT` |
| บทวิเคราะห์รายเดือนในหน้า `วิเคราะห์` | เฉพาะตอนผู้ใช้กดปุ่ม แคชตามตัวเลข จำกัดวันละ 10 ครั้งต่อคน | `LLM_PROVIDER` / `LLM_MODEL` |
| อ่านสลิปจากรูป | ทุกสลิปจนถึงเพดานต่อคน ถ้าไม่มีคีย์/เกินเพดาน/เรียกไม่สำเร็จจะถอยไปใช้ Tesseract | `GEMINI_API_KEY` / `OCR_PROVIDER` / `OCR_MODEL` / `OCR_DAILY_LIMIT` |

การอ่านสลิปตั้งแยกจาก parser จึงใช้ Claude อ่านข้อความและ Gemini อ่านสลิปพร้อมกันได้

ทั้งสามงานส่งเข้าโมเดลเฉพาะเท่าที่จำเป็น บทวิเคราะห์ส่งแค่ยอดรวมรายหมวด ไม่มีรายการเดี่ยว โน้ต หรือชื่อร้าน
parser จำกัดข้อความ 500 ตัวอักษรและผลลัพธ์ 150 token โดยค่าเริ่มต้น พร้อมเก็บเฉพาะจำนวน call, input/output token, provider, model และ error ใน `llm_usage` ไม่เก็บ prompt หรือข้อความการเงินใน metric

## หน้าวิเคราะห์

หน้า `วิเคราะห์` (`/insights`) เทียบรายจ่ายรายหมวดของเดือนที่เลือกกับเดือนก่อนหน้า
เรียงตามขนาดที่เปลี่ยนไป ไม่ใช่ตามยอดที่ใหญ่ที่สุด แล้วต่อด้วยโดนัทสัดส่วนและกราฟรายวันชุดเดิม

ปุ่ม `วิเคราะห์ให้หน่อย` เรียก LLM เขียนสรุปว่าเดือนนี้เงินไปไหน อะไรเปลี่ยนไป
และมีรายการไหนลดได้ประมาณเท่าไรต่อเดือน ผลถูกเก็บไว้พร้อม fingerprint ของตัวเลข
เปิดหน้าซ้ำจึงไม่เสียค่า API และถ้ามีรายการใหม่เข้ามา หน้าจะบอกว่าบทวิเคราะห์เก่ากว่าตัวเลขปัจจุบันแล้ว

ถ้าไม่ได้ตั้งคีย์ หน้านี้ยังใช้ได้ทุกอย่างยกเว้นบทวิเคราะห์

## หมายเหตุด้านเวลา

ทุกการรวมยอดรายวันคิดตามเวลา **Asia/Bangkok (UTC+7)** ไม่ใช่ UTC
มิฉะนั้นรายการช่วง 00:00–06:59 น. ของไทยจะถูกนับเป็นวันก่อนหน้าเมื่อใช้วัน UTC
timestamp เก็บเป็น `timestamptz` แล้วแปลงตอน group by ใน Postgres

## ความปลอดภัย

- webhook ตรวจ `x-line-signature` (HMAC-SHA256) ก่อน parse body เสมอ
- `webhookEventId` และการเพิ่ม/ลบรายการ commit ใน transaction เดียวกัน ถ้าบันทึกล้มเหลวจะ rollback และตอบ 503 เพื่อให้ LINE retry เมื่อเปิด Webhook redelivery
- เวลาอ้างอิงของข้อความใช้ timestamp เดิมจาก LINE เพื่อไม่ให้ retry ข้ามวันเปลี่ยนวันที่รายการ
- ข้อความยืนยันส่งหลัง commit; ถ้าส่งยืนยันล้มเหลว รายการยังอยู่ แต่ยังไม่มีระบบ retry ข้อความยืนยัน
- แดชบอร์ดปิดด้วย password + signed cookie ผ่าน `hooks.server.ts`
- ไม่มี secret ใน source — อยู่ใน `.env` ซึ่ง gitignore ไว้แล้ว

```bash
bun run dev            # dev server

bun run test:run       # unit tests
bun run check          # type check (svelte-check)
bun run build          # production build
bun run db:push        # sync schema เข้า DB (dev)
bun run db:generate    # สร้างไฟล์ migration
bun run db:seed        # seed หมวดหมู่
bun run db:down        # หยุด Postgres
bun run db:backup      # สร้าง logical dump ไป S3-compatible bucket หรือ BACKUP_LOCAL_DIR
bun run db:restore-check # กู้ dump ล่าสุดลงฐานข้อมูลทดสอบและตรวจ schema
```
